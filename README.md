# Deploy LiteLLM on OCI

This Terraform root deploys a production-oriented LiteLLM gateway on an OKE
enhanced cluster. It provisions private worker, pod, PostgreSQL, and Redis
networks; OCI Database with PostgreSQL; OCI Cache with Redis; OCI Vault
secrets; an OCI-managed certificate; OCI WAF; a public OCI flexible load
balancer created by the OCI Native Ingress Controller; and OCI DNS.

LiteLLM listens on port `4000`. The load balancer terminates public HTTPS and
forwards HTTP to the private OKE pods. Worker and pod egress reaches OCI
services through a Service Gateway and OCI Generative AI through a NAT Gateway.

## Prerequisites

- Terraform 1.5.7 or later.
- OCI CLI available to the Kubernetes and Helm providers for OKE token
  generation.
- Network access from the Terraform runner to the private OKE API endpoint.
- An OCI API-signing user in the IAM group referenced by the Generative AI
  policy.
- A publicly trusted certificate and private key to import into OCI
  Certificates.
- An owned public DNS zone that can be delegated to OCI DNS.
- A supported OKE worker image OCID for the selected region and Kubernetes
  version.

The committed DNS hostname uses `example.com` and cannot be delegated. Replace
it before applying. The certificate example also contains placeholders and is
not deployable until real PEM material is supplied in an uncommitted tfvars
file. Imported certificate private-key material is stored in Terraform state,
so use an encrypted remote backend with tightly scoped access.

## Configure

Copy every `*.auto.tfvars.example` file to the same name without `.example`,
then replace the redacted values. Real `*.tfvars` files are ignored by Git.

The PostgreSQL password, LiteLLM master key, and immutable LiteLLM salt are
generated by OCI Vault. The OCI API signing private key is imported into Vault
from base64 content supplied through the uncommitted `vault.auto.tfvars` file.
The Redis password is also imported into Vault; configure the matching bcrypt
hash in `redis.auto.tfvars` so OCI Cache and LiteLLM use the same credential.

The LiteLLM salt must not be changed after credentials have been stored in the
database. Doing so makes the stored credentials unreadable.

## Deploy

```shell
terraform init
terraform plan -out=litellm.tfplan
terraform apply litellm.tfplan
```

The Secrets Store CSI Driver and OCI provider are installed first. A dedicated
Helm release mounts the OCI Vault secrets and synchronizes a Kubernetes Secret.
The LiteLLM release then runs a pre-install/pre-upgrade Prisma migration Job.
All serving replicas run with `DISABLE_SCHEMA_UPDATE=true`.

After apply, delegate the public zone to the nameservers in the `dns_zones`
output if delegation was not already configured. DNS propagation is external
to Terraform.

## Operational notes

- The OKE API endpoint is private by default. Run Terraform from a connected
  OCI network, VPN, or bastion-based execution environment.
- The Redis subnet is dedicated because OCI Cache can leave a service-managed
  security list that may need separate cleanup during destroy.
- Pin the LiteLLM image and OCI CSI provider Helm chart version. Test upgrades in a
  non-production workspace before changing them.
- The OCI Native Ingress Controller attaches the WAF policy and OCI
  Certificates certificate to the load balancer it creates.
